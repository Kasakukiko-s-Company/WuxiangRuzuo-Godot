# P1 可玩体验原型规格

状态：2026-07-20 已在工作区实现并自动验收；尚未提交或推送，未进入 P2。

## 单一体验命题

验证玩家在一段新设计的雾乡边缘灰盒中移动、观察、靠近地标并交互时，操控、镜头、空间尺度、像素密度和基础视听反馈是否足以支撑“愿意在这里生活和继续探索”的第一印象。

P1 不迁移旧 `mvp_farm`，也不把 `home_interior`、`hometown_main` 等旧四图当默认答案。

## 可玩入口

- 独立场景：`res://scenes/prototypes/p1_experience_probe.tscn`。
- 默认项目 Main 保持可启动，并提供进入 P1 原型的明确开发入口。
- 原型区域工作 ID：`prototype_mist_edge`，不得误登记为正式世界地图。

## 灰盒空间

约 40×28 个基础格的单一区域，包含：

- 一个室内/安全空间出口或门廊轮廓。
- 一块可穿行的生活空地与未来生产区轮廓。
- 一段有宽窄变化和转角的道路。
- 水边或地形边界，用于验证碰撞和构图。
- 前后景遮挡、窄通道、开放空间和一个远近都可辨识的地标。
- 6～10 个可检查对象，用短反馈验证面对方向、交互距离和输入恢复。

这些元素服务运动/空间验证，不承诺成为正式地图内容。

## 功能范围

- `CharacterBody2D` 四方向自由移动、对角归一化、加减速/立即响应方案可比较。
- 静态碰撞、贴墙滑动、窄通道和边界阻挡。
- `Camera2D` 平滑跟随、限制、像素稳定与必要的 reduce-motion 方案。
- 语义 InputMap：移动、交互、主要动作、暂停和调试开关；键盘和手柄使用同一 gameplay command。
- 面向方向、目标点/目标格、world/local/map 坐标转换和调试叠层。
- 通用可交互对象协议：检查文本、一次性/重复反馈、输入锁定与可靠恢复。
- `prototype_mist_edge` 的进入、重置和安全出生点。
- 基础画质开关 seam；关闭粒子/雾表现仍能识别路径、碰撞和交互。

## 代表性资源小包

P1 可以新制而不是复用旧候选，但只生产足够验证方向的样本：

- 一套灰盒与质量标杆之间的环境小包：地面、道路、水/边界、建筑轮廓、树/灌木、前景遮挡和地标。
- 一个代表玩家 Sprite：至少四方向 idle/walk；画布与像素密度可在两种方案中比较。
- 6～10 个交互物图形或清楚占位。
- 一段可循环环境声景、脚步/交互/UI 基础音效，以及一段用于测试日常氛围的音乐草稿。
- 资源全部进入 brief、来源台账和技术规格；未获方向批准的候选不进入正式 `assets`。

## 自动验收

- Godot 4.7.1 stable headless 导入、全项目 GDScript parse 和原有 G1/G2 回归通过。
- 输入向量归一化，四方向/对角速度符合规格；暂停或交互锁定时不泄漏移动。
- 碰撞不会穿墙，贴墙滑动可预测；出生点不与障碍重叠。
- Camera2D limits 覆盖灰盒边界，重置/重进后结果确定。
- world/local/map 转换有往返测试；面对目标在四方向和边界格上正确。
- 所有交互结束、中断和重置路径恢复输入。
- Compatibility Renderer、640×360 逻辑视口和质量回退不回归。

## 实际运行验收

- 以键盘和手柄分别完成出生点 → 地标 → 水边 → 窄通道 → 返回的完整路径。
- 连续贴墙、快速换向、窗口缩放和暂停恢复无明显抖动、卡死或输入残留。
- 640×360、2×窗口和代表性低档画质下，角色、道路、遮挡和交互目标清楚。
- 截取固定机位对比图并记录角色画布、Tile 尺度、相机平滑和前景遮挡的选择依据。
- 运行日志无解析错误、孤立错误和未处理资源缺失。

工程任务自行执行上述运行、截图和日志检查；只有两种美术/手感方案都技术成立且方向差异明显时，才集中请用户选择。

## 明确不做

- 不实现完整农耕、经济、跨日、正式存档文件或 HUD。
- 不在 P1 提前实现战斗；这只是阶段排序，战斗已确认并由 P4 强制交付完整垂直切片。
- 不生产正式世界全量 TileSet、NPC 阵容、立绘套装或完整音乐。
- 不实现旧四地图切换、旧界碑异常或旧矿道。
- 不承诺 P1 灰盒、角色外观或音乐草稿直接进入正式版。

## P1 出口

形成一份基于运行证据的规格决策：移动模型、速度/响应、碰撞策略、Camera2D 行为、基础格/角色像素密度、地图转换 seam、交互距离、代表性美术方向和基础音频方向。只有这些决策被记录并通过回归，才能进入 P2。

## P1 验收结果与采用决策

- 移动采用立即响应、96 px/s、对角归一化；输入锁定时速度归零。后续可以在不改变 `MovementIntent` 语义的前提下比较加速度，但 P2 默认沿用立即响应。
- 碰撞采用 `CharacterBody2D.move_and_slide`；当前玩家碰撞脚印约 18×20 px，允许贴墙滑动。视觉画布与物理脚印分离。
- 基础格保持 32×32；角色正式源画布仍以 96×96 为首版生产约束，运行时可见身体约占 28×48 px。P1 程序化角色只验证密度和读形，不是角色定稿。
- Camera2D 平滑速度采用 8.0，边界严格限制在 1280×896 灰盒；reduce-motion 关闭平滑但不改变玩法。
- 交互目标是面对方向相邻一格；world/cell/cell-center/facing-cell 全部经 `TileCoordinateMapper`，不把像素坐标写入领域规则。
- 输入以 `InputSnapshot` 为唯一玩法语义；键盘与手柄绑定只存在于 Godot adapter，不进入玩家控制器。
- 高画质增加局部地面差异、雾带和轻量环境细节；低画质关闭这些附加项但保留路径、角色、遮挡边界和提示。
- 环境低频循环、脚步和交互提示音证明了音频反馈 seam 与基础动态层次；其旋律、配器和正式混音尚未定稿，后续资源生产不得把程序波形当正式配乐。
- `prototype_mist_edge`、8 个交互物与全部程序图形只作为验证证据，不升级为正式正史、正式地图或正式资源。

完整命令、35 项 P1 行为检查、99 项前序回归和实际渲染证据见 `docs/P1_VERIFICATION.md`。
