# 《雾乡如昨》完整游戏制作路线

## 路线原则

- G0～G2 是已经完成的技术底座历史，不是产品完成度刻度。
- 旧 G3～G13 停止使用；新阶段围绕玩家体验和完整游戏交付组织，不围绕 Cocos 文件逐项翻译。
- 每阶段必须同时交付可玩入口、必要内容/资源、自动验证、实际运行验证和明确的不做项。
- 占位资源可以帮助验证规则，但不能把“能运行”当作“内容完成”。
- 世界功能拓扑、居民可发现性和 AI 辅助资源准入统一参考 `DESIGN_REFERENCE_LESSONS.md`；外部案例只提供待验证的方法，不定义本项目地图、角色、数值或美术。

## P0：产品重基线与前期制作

定义完整游戏愿景、核心玩家、体验比例、世界/叙事结构、内容预算、视听质量标杆和平台优先级；建立重大问题的原型验证清单及 P1 规格。

出口：产品愿景、产品 brief、制作路线、内容/资源策略和初始预算包络获确认；决策状态清楚；`P1_EXPERIENCE_PROTOTYPE.md` 的单一体验命题和验收标准获准实施。

## P1：体验原型

在一张为验证而设计的灰盒区域中完成移动、碰撞、相机、交互和基础反馈，重点验证操控手感、视距、节奏、空间尺度与美术像素密度。地图不必沿用旧四图之一。

出口：可独立运行和回归；操控与空间标尺明确；形成继续、修改或推翻当前视觉/地图假设的证据。

## P2：核心生活循环垂直切片

实现一个具有实际选择和反馈的完整生活日：资源获得、耕作/生产、背包、时间推进、保存恢复和必要 UI，并配一组达到代表性质量的场景、角色、动画和声音。

出口：循环有可玩价值而非仅能调用；事务、跨日和存档可测试；首次形成内容生产成本基线。

## P3：城镇与关系垂直切片

实现代表性居民的条件化日程、默认回退、对话、事件、居民知识、偏好发现、关系变化和世界反馈，验证人物内容管线与游戏内信息可发现性。使用少量高完成度代表角色，不承诺旧 15 人全部保留。

出口：人物行为与关系能跨日持续；对白/立绘/动画/配音策略（若采用）成本可量化；内容工具可重复使用。

## P4：探索与叙事垂直切片

实现一段从日常主动进入调查、获得线索、进入完整战斗遭遇并安全返回的节奏。战斗必须覆盖玩家攻击/能力、敌人行为、伤害状态、奖励、成长和失败恢复；同步比较实时/回合/混合操控与难度方案，并决定旧异常和旧矿道是否值得重写保留。

出口：悬疑不靠文字说明单独成立；战斗具有明确输入、策略、反馈、奖励和恢复闭环；玩法、环境叙事、音乐与音效共同工作；重大不可逆状态有清楚回退。

## P5：生产管线与质量标杆

固化地图、事件、对白、本地化、资源家族、美术、动画、音频和构建管线；明确区分方向参考板、人工重构源文件与获准运行时资源；制作一个接近最终质量的代表区域和完整内容样章。

出口：内容团队可以按模板持续生产；资源预算、命名、授权、导入、性能和回退标准可执行；不再依赖临时手工流程。

## P6：Alpha——全流程可玩

以占位或不同完成度资源打通完整游戏，从开场到所有计划结局都能游玩；主要系统、区域、角色弧和任务结构均已存在。

出口：没有阻断流程的缺口；存档升级和恢复可靠；范围冻结，新增需求必须替换同等成本内容。

## P7：内容完成

完成所有正式地图、事件、对白、角色表现、物品/作物/经济内容、美术、动画、音乐、环境音、音效和必要本地化文本。

出口：不再依赖面向玩家的占位内容；全内容审查、来源台账和资产覆盖矩阵通过。

## P8：Beta——平衡、可用性与优化

集中处理平衡、引导、可访问性、输入、性能、兼容性、存档健壮性、错字、穿帮、音频混音和长流程回归。

出口：已知问题可控；目标硬件性能达标；外部试玩反馈完成闭环。

## P9：Windows/Steam 发行候选

完成导出、安装/卸载、Steam adapter、成就/云存档决策、商店素材、法律与隐私检查、崩溃信息和发布回滚方案。

出口：候选构建可重复生成并通过发行清单；只有用户明确批准才发布。

## Windows/Steam 之后的 Web/微信路线

用户已确认将 Web/微信的实际开发与发行验证后置到 P9 Windows/Steam 发行候选之后。P2～P9 不下载 Web 导出模板、不安装微信插件、不进行渠道适配，也不承诺 PC 与微信同步发布；只继续保持 Compatibility Renderer、平台/存档/输入/音频 adapter、画质回退和核心玩法不依赖 `window`/`localStorage`/`wx` 的架构边界。

后置路线独立编号，不改变 P0～P9 的完成状态：

- **W0 标准 Web 可行性**：使用届时与编辑器完全一致的稳定版官方模板，验证启动、包体、内存、渲染、输入、音频解锁、浏览器存档和生命周期。
- **W1 微信可行性**：只有 W0 成立后，才审计微信运行容器、包体/分包、WebGL、触控与安全区、存储、网络/隐私、审核规则、维护成本和任何候选适配方案的来源/许可证。
- **W2 发布决策**：根据证据选择正式支持、安排专项移植或暂不发布；任何外部发布仍需用户明确批准。

后置策略接受届时可能需要压缩资源、调整音频或修改平台 adapter 的成本，但这些结果不得阻塞 Windows/Steam 完整版交付。
