# 旧 Demo 存档与历法设想（历史参考）

> 三档、四季×30 日和事件保存点是旧方案，不自动成为完整游戏最终规则。新的存档可靠性要求继续有效，具体档位、历法、时间系统和恢复体验需随完整游戏结构重新确认。

## 三档目标

稳定档位为 `profile-1`、`profile-2`、`profile-3`。每档逻辑包含 metadata、currentSnapshot 和可选 protectedRecoverySnapshot；当前 Demo 后者为空。`lastPlayedProfileId` 与用户设置属于全局数据。

一个档损坏不阻塞其他档；最近档损坏时进入档位界面并明确原因，不能静默跳档。三个快照不能嵌入一个必须整体解析的共同 JSON。新档、读档、删除和保存都要可回读验证。

## 自动保存边界

只在稳定状态保存：新档初始化完成；睡觉/跨天事务完成；界碑回折已安全落点并提交状态；稳定状态下保存并返回标题。捕获、编码、写入或回读失败均保留旧快照。后台保存是最佳努力，不是唯一保障。

Windows adapter 采用同目录临时文件+替换/重命名或等价原子策略；Web/微信 adapter 保持同一语义。损坏档写入保持锁定，直到用户删除、成功迁移或从受保护恢复点恢复。

## 旧 Cocos 档

旧 `autosave`/SaveData v1 不由新 SaveCodec 直接读取。未来只通过显式 `CocosSaveImporter` 导入空档，进行全有或全无转换、写入、回读和运行时恢复验证；失败保留旧 payload。旧 `mvp_farm` 坐标不能直接投影到正式地图。

## 历法

四季 spring/summer/autumn/winter，每季 30 日，每年 120 日。开场 `worldDay=1`（第 1 年春 1 日）。存档只保存一基累计 `worldDay`，年/季/日确定性推导。睡觉顺序：结算旧日作物 → worldDay+1 → 新日期/生日 → 新日重置/传送 → 原子保存。

乔苓开场 17 岁、生日为年内第 1 日，`worldDay=121` 满 18；不得自动告白或重释儿童期内容。

## 里程碑与恢复点

第一处异常完成后自动保存，返回日常显示非阻塞“继续生活/返回标题”，默认继续；不会自动进入真相期。当前异常不创建保护点。未来不可逆确认必须先创建、回读验证受保护恢复点，否则内容不得开放。

## 当前事实

G2 已有纯领域 `SaveSnapshot`/`SaveCodec`，但没有 SaveService、档位文件、自动保存、历法推进或恢复流程。P2 必须为生活循环建立真实保存恢复，P6 前必须覆盖全流程和 Schema 升级；不得把 codec 往返测试或旧单槽技术 MVP 当作可玩的存档能力。
