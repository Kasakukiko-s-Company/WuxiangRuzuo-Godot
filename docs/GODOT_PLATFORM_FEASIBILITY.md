# Godot 平台可行性边界

## 当前结论与顺序

G2 证明本机 Windows 上 Godot 4.7.1 stable 项目可解析、启动并通过平台契约测试，但没有实现发行 adapter。尚未执行 Windows 导出、Steam SDK 接入、Web 导出或微信小游戏真机验证。

用户已确认：P2～P9 专注 Windows/Steam 完整游戏；标准 Web 与微信的实际开发后置到 P9 发行候选之后。当前不下载 Web 模板、不安装微信插件、不做渠道适配、不承诺微信发行，只维护 Compatibility Renderer、平台 adapter 和画质回退等低成本兼容边界。

## Windows PC

目标为 Compatibility Renderer + GDScript 的原生 Windows 构建。P9 发行候选需要同版本导出模板、构建到 D 盘、键盘/手柄/窗口模式、存档原子性、性能和干净机器运行验证；早期代表构建可按阶段需要提前验证。目前属于高可行性目标，但不是已完成交付链路。

## Steam

Steam 是 `windows-native` 环境下的发行渠道。P9 完成 Steamworks adapter、overlay、成就、云存档冲突策略与商店构建决策；核心玩法和 SaveCodec 不得直接依赖 Steamworks。

## Web

Web 是独立运行环境，受浏览器存储、线程、内存、音频解锁、文件系统和生命周期限制。P9 后的 W0 才下载与届时 Godot 稳定版完全一致的官方模板，验证启动、输入、音频、保存、前后台、包体和性能。W0 之前不把 Web 导出列入阶段验收。

## 微信小游戏

不能假设 Godot 4.7.1 原生支持微信小游戏，也不能把普通 Web 导出等同于微信发布。只有 W0 标准 Web 验证成立后才进入 W1，并独立验证包体/分包、WebGL/渲染能力、触控与安全区、音频、存储配额、生命周期、网络/隐私合规、审核规则与维护成本。

在完成来源、许可证、版本兼容、可维护性和最小原型审计前，不安装任何“微信导出插件”。若只能依赖高风险第三方 fork/插件，应把它作为发行决策而非默认工程依赖，并保留 Windows/Web 能力抽象。

W2 根据 W0/W1 证据选择正式支持、专项移植或暂不发布。后置路线失败或成本过高不得阻塞 Windows/Steam 发行候选。

## 画质档位

计划至少提供 `low`/`medium`/`high`：粒子、动态灯光、Shader、雾带数量和后处理可关闭。画质只能改变表现，不得改变碰撞、异常结果、作物成长或战斗规则。
