# Godot 平台可行性边界

## 当前结论

G2 证明本机 Windows 上 Godot 4.7.1 stable 项目可解析、启动并通过平台契约测试，但没有实现发行 adapter。尚未执行 Windows 导出、Steam SDK 接入、Web 导出或微信小游戏真机验证。

## Windows PC

目标为 Compatibility Renderer + GDScript 的原生 Windows 构建。G11 需要同版本导出模板、构建到 D 盘、键盘/手柄/窗口模式、存档原子性、性能和干净机器运行验证。目前属于高可行性目标，但不是已完成交付链路。

## Steam

Steam 是 `windows-native` 环境下的发行渠道。G13 才评估 Steamworks adapter、overlay、成就、云存档冲突策略与商店构建。核心玩法和 SaveCodec 不得直接依赖 Steamworks。

## Web

Web 是独立运行环境，受浏览器存储、线程、内存、音频解锁、文件系统和生命周期限制。G12 先用不含来源不明插件的官方 Web 能力验证启动、输入、音频、保存、前后台和性能。

## 微信小游戏

不能假设 Godot 4.7.1 原生支持微信小游戏，也不能把普通 Web 导出等同于微信发布。G12 必须独立验证：包体/分包、WebGL/渲染能力、触控与安全区、音频、存储配额、生命周期、网络/隐私合规、审核规则与维护成本。

在完成来源、许可证、版本兼容、可维护性和最小原型审计前，不安装任何“微信导出插件”。若只能依赖高风险第三方 fork/插件，应把它作为发行决策而非默认工程依赖，并保留 Windows/Web 能力抽象。

## 画质档位

计划至少提供 `low`/`medium`/`high`：粒子、动态灯光、Shader、雾带数量和后处理可关闭。画质只能改变表现，不得改变碰撞、异常结果、作物成长或战斗规则。
