# 《雾乡如昨》产品 Brief

## 状态

P0 工作假设，服务于原型与产能验证。用户已确认“制作完整游戏、旧 Cocos 仅作雏形参考、必要时扩充内容与视听资源”的总方向；本文的时长、比例和内容范围不是不可修改的承诺。

## 一句话产品

一款以宁静乡村生活为日常底色、以有主体性的居民关系为情感核心、由玩家主动深入雾中异常并承担选择后果的 2D 单机游戏。

## 目标玩家

- 喜欢慢节奏生活模拟、整理与成长反馈，但希望重复劳动背后有世界变化的玩家。
- 重视人物、氛围和选择，希望悬疑可自主推进而不是持续强迫追主线的玩家。
- 接受轻量探索/危险，但不要求高强度动作战斗或复杂操作门槛的玩家。
- 首发使用 Windows PC，键盘/手柄均能完整游玩；Steam 为首要发行渠道。

## 体验比例假设

以玩家实际游玩时间估算：

- 生活生产、经营与空间成长：约 45%～55%。
- 居民交往、事件与关系选择：约 20%～25%。
- 探索、调查、谜题与主线推进：约 15%～20%。
- 战斗、敌人与战斗成长：约 8%～12%，一定存在，但保持可理解、可恢复且不吞噬生活模拟主体。

这些比例用于防止悬疑吞噬日常，或生活系统沦为主线间的机械等待；不是每个小时的硬配额。

## 时长与节奏假设

- 主线完整体验：18～25 小时。
- 包含主要关系线和可选内容：35～50 小时。
- 常见单次游玩：20～60 分钟；短时间也应能完成一个有意义的小目标并安全保存。
- 不以无尽重复、随机刷取或强制每日打卡延长时长。

P2/P3 完成后必须用真实制作速度和玩家节奏重估；若高质量内容无法支撑该区间，优先缩短而不是稀释。

## 完整玩家旅程

1. **安顿与理解**：玩家掌握移动、生活生产、时间、存档和基本关系，世界给出清晰安全感。
2. **扎根与扩展**：生活选择、居民关系和空间/生产能力产生可见成长，更多区域与故事入口开放。
3. **裂隙与选择**：异常逐渐与日常、人物和过去发生联系；玩家决定调查深度、信任对象和承担的风险。
4. **真相与收束**：生活积累和关系选择参与最终冲突或抉择，形成可理解的结局差异。
5. **结局后处置**：提供清楚的存档/回退/继续生活方案，不让玩家因进入结局永久失去长期经营成果。

这五段是功能结构，不预设旧叙事 Bible 的真相、角色分类或固定事件仍然成立。

## 必须成立的系统群

- 角色移动、交互、相机、输入和空间可读性。
- 时间推进、生活生产、资源获得、库存/工具和有意义的成长反馈。
- 经济或等价资源交换/消耗结构，防止产出没有长期用途。
- 居民日程、对白、关系状态、事件和世界反馈。
- 探索、线索、条件、选择、后果与安全回退。
- 战斗输入、攻击/能力、伤害与状态、敌人行为、成长、奖励、失败恢复和必要战斗 UI/视听反馈。
- 世界状态、任务/事件调度、保存恢复和 Schema 升级。
- 标题、档位/继续、HUD、设置、输入重映射或可替代方案、字幕、音量、画质与减弱动态效果。
- 正式美术、动画、音乐、环境音、音效、本地化准备和发行构建。

## 需要原型后决定的系统

- 战斗采用实时、回合或混合形式；武器/能力、敌人、难度、成长、失败成本和生活系统联动深度。
- 商店/货币、制作、烹饪、钓鱼、畜牧、住宅或村庄建设各自的深度。
- 连续时钟、行动点或混合时间制；天气与季节是规则还是主要为内容表现。
- 恋爱、同居/婚姻、节日、同伴等高内容成本系统的覆盖范围。
- 主线结局数量、关系结局组合和结局后世界状态。

## 质量承诺

- 玩家看到的内容不以工程占位符冒充完成品。
- 同一规则在键盘、手柄及未来触控 adapter 下保持语义一致。
- 重要信息不只依赖颜色、声音、粒子或高画质效果。
- 存档失败、内容缺失、场景切换失败和不可逆选择都有受控恢复。
- 资源来源、商业许可和修改记录完整；未知来源内容不进入发行包。

## 平台顺序

Windows PC/Steam 是 P2～P9 的正式开发和发行主线。Web/微信实际开发后置到 Windows/Steam 发行候选之后：先验证标准 Web，再验证微信渠道，最后决定正式支持、专项移植或暂不发布。后置验证前只保持 Compatibility Renderer、平台 adapter 和表现回退，不下载模板、不安装微信插件，也不承诺微信版本。
