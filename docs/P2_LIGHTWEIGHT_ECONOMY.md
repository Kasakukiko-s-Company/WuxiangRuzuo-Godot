# P2 H01 轻量交换闭环

## 状态

2026-07-29 已在 H01 正式运行切片中加入第一条可兑现的生产—交换—补充路径：

`选择当日资源 → 种植与跨日成长 → 收获雾叶 → 北草甸物资箱交换 → 获得村社券 → 回购雾叶草种子`

这条路径用于验证领域交易原子性、稳定配置、Godot 场景桥接、反馈服务和现有存档恢复，不代表完整游戏经济、正式商店或最终货币方案已经确定。

## 当前交换项目

数据入口为 `data/trade_offers.json`，当前稳定端点为 `economy.h01.north_meadow_crate`：

| 稳定 ID | 支出 | 获得 |
| --- | --- | --- |
| `economy.h01.sell_mistleaf` | 雾叶×1 | 村社券×30 |
| `economy.h01.buy_mistleaf_seed` | 村社券×20 | 雾叶草种子×1 |

北草甸当日资源选择尚未领取时，物资箱优先打开每日二选一；当日领取完成后，同一交互点第一次 E/A 打开交换、Q/Tab 或手柄肩键切换、第二次 E/A 确认。移动、使用物品、快捷栏切换、重置或其他目标交互会取消未确认交换。

## 领域边界

- `TradeOfferCatalog` 只接受非空、正数量、不同收支物品、已存在物品引用和全局唯一 offer ID。
- `TradeBook.offers(endpoint_id)` 提供端点可见项目；`execute(inventory, command)` 执行一项交换。
- 交换先从不可变背包移除支出，再尝试加入所得；所得放不下时返回调用前的原背包对象，不留下部分扣除。
- 支出清空槽位后，所得可以使用刚释放的槽位。
- offer 不能在错误端点执行；未知 offer、数量不足和容量不足都有明确结果状态。
- 场景只保留可取消的选择索引；价格、物品和数量来自受验证目录，不在 Node 中临时拼装规则。
- 当前交换本身不设每日次数限制，也不写入每日使用记录；可交易次数只受背包现有物品约束。每日限制仅属于北草甸资源二选一。未来营业时间、每日限额或剧情门槛必须通过新的受验证策略扩展，不能塞进瞬时 UI 状态。

## 村社券与存档边界

`village_scrip` 当前是 `material` 类型的本地交换凭证，直接占用普通背包槽位。它不是已经确认的全游戏通用货币，也没有独立钱包、账户或平台支付语义。

因此本批没有修改存档 Schema：Godot `schemaVersion: 2` 已能通过普通 inventory slots 保存和恢复村社券。未来若产品验证决定引入全局钱包，必须另做显式 Schema 设计和迁移，不能暗中改变 `village_scrip` 的现有语义。

## 尚未关闭的产品问题

- 每日免费资源与回购价格如何形成真正有压力但不惩罚新玩家的节奏。
- 村社券是否保留为地方凭证、被正式货币替代，或仅用于早期互助交换。
- 正式商店地点、NPC、营业时间、批量交易、价格变化、升级和任务门槛。
- 多作物、加工品、采集品、制作与战斗掉落如何共同进入经济。
- 玩家实际游玩后，对“即时领取”与“延迟种植”的选择是否有意义。
- 如果背包满到两个免费资源选项都无法容纳，玩家当前也无法先进入交换腾出槽位；节奏验证前需要增加显式“转到交换”入口，或证明至少一个当日选项始终可容纳。

这些问题需要后续产品原型和玩家验证；当前实现只建立可运行、可替换的深模块接口。
