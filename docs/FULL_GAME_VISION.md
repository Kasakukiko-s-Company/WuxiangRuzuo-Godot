# 《雾乡如昨》完整游戏愿景

## 文档地位

本文件是 Godot 正式版的产品重基线。旧 Cocos 工程、旧 Demo 范围、四地图拓扑、15 名 NPC 清单和既有切片均为候选输入，不是范围上限，也不会仅因已经存在就自动进入正式版。

当前重基线定义方向和完整度门槛。`PRODUCT_BRIEF.md` 与 `CONTENT_BUDGET.md` 提供可调整的时长、角色、区域和资源包络；这些数字必须通过可玩原型、制作估算和玩家验证校准，不能升级为不可变铁律。

## 产品承诺

《雾乡如昨》应成为一款可以从开场持续游玩到完整收束、日常生活本身有吸引力、关系变化有反馈、主动探索能推动悬疑的完整 2D 游戏。玩家不是在体验一组迁移后的系统样例，而是在经历一个有成长、选择、情绪节奏和结局回响的世界。

## 核心体验支柱

1. **可持续的乡村生活**：劳动、经营、整理、成长和空间变化形成长期而非一次性的满足感。
2. **有主体性的居民与关系**：人物拥有日程、需求、事件、记忆与关系变化，不只是功能 NPC 或线索容器。
3. **由玩家主动推进的悬疑**：日常和调查都能成立，玩家理解风险并决定何时深入，线索、环境和关系共同承载叙事。
4. **探索与战斗带来新的玩法与世界理解**：战斗是完整游戏的确定组成部分；区域、资源、谜题、敌人和战斗成长必须服务于生活积累、人物选择和叙事，而不是孤立的旧矿道样例。
5. **视听共同塑造雾乡**：场景美术、角色表演、音乐、环境音、音效、光色和节奏都是产品内容，不是开发结束后的装饰。

## “完整游戏”的出口定义

正式版至少需要同时满足：

- 有从新游戏、教学、成长、关键转折到结局及结局后处置的完整玩家旅程。
- 核心生活循环具备足够的选择、成长、反馈和内容变化，不靠重复同一小切片填充时长。
- 世界空间、居民关系、任务/事件和主线调查能够互相影响，而非各自孤立。
- 存档、设置、输入、可访问性、本地化准备、性能、错误恢复和发行流程达到可交付标准。
- 正式美术、动画、UI、字体、音乐、环境音、音效和必要演出均通过来源、质量、性能和平台验收。
- 游戏内容从开场到结局均可玩、可理解、可恢复，并经过系统测试、内容检查和真实游玩验证。

## 旧原型的取舍规则

| 旧内容 | 当前地位 | 正式版处理方式 |
| --- | --- | --- |
| G2 强类型数据、领域模块、平台接口 | 可复用技术底座 | 继续测试和深化，不让旧数据规模约束接口 |
| 四地图拓扑 | 灰盒种子/测试 fixture | 可扩充、合并、替换或废弃，由世界结构决定 |
| 15 名 NPC | 候选人物池 | 按角色功能、人物弧、制作成本和多样性重新选定 |
| 第一处结界异常 | 候选叙事事件 | 在完整悬疑节奏中重新定位、重写或替换 |
| 旧矿道与基础战斗 | 矿道/旧规则为候选；战斗本身已确认 | P4 重新设计并验证战斗形态、节奏、成长和规模，不默认沿用旧实现 |
| 旧叙事 Bible | 创意素材 | 重新做主题、结构、角色和结局一致性审查 |
| 旧像素/立绘规格与候选图 | 视觉假设与参考 | 通过质量标杆、运行测试和授权审核后再采用 |

## P0 必须回答的产品问题

- 生活模拟、关系叙事、悬疑调查和战斗各自占多大比重。
- 目标玩家、目标游玩时长、主线结构、结局结构与结局后玩法。
- 世界由哪些区域构成，区域如何随剧情、季节或建设变化。
- 农业、采集、制作、经济、住宅/村庄发展等系统需要怎样的深度。
- 正式角色阵容、关系深度、日程、事件量和对白生产预算。
- 战斗采用何种操控、武器/能力、敌人、难度、频率、成长、失败成本和内容规模，以及如何与生活/关系/调查互相作用。
- 美术精度、动画密度、立绘覆盖、音乐系统、音频覆盖和本地化目标。
- Windows/Steam 的首发目标，以及 Web/微信在性能、输入、包体和渠道能力上的独立可行性结果。

当前答案、工作假设和原型问题记录在 `PRODUCT_BRIEF.md` 与 `P0_DECISION_LOG.md`。这些问题优先通过短周期可玩验证、内容样章和制作成本估算解决。能自动检查或由实际运行验证的事项由工程任务处理，只把不可替代的创意取舍集中交给用户确认。
